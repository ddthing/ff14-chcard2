# Cloudflare Pages

This project exports static HTML for the routes generated by Next.js. Editor state, image adjustments, preview rendering, and card exports run in the browser; this version does not require a Next.js server or account API.

1. Connect the GitHub repository in Cloudflare Workers & Pages and create a Pages project.
2. Set the production branch to `main` and the root directory to `/`.
3. Use `npm run build` as the build command and `dist` as the build output directory. (Next.js also writes the same static export to `out`.)
4. Leave `.env.local` and `.dev.vars` out of GitHub. The build uses the default `false` for the optional official FFXIV asset flag unless you configure it explicitly; with the default, it omits those opt-in binaries from the exported site.

Cloudflare's Next.js Pages guide calls this deployment mode a static export. The production Next configuration uses `output: "export"` and disables Next's server image optimizer so images ship as static assets. The project route scan finds no route handlers or server APIs. Validate the Cloudflare preview deployment before assigning a custom domain.

If the app later needs server rendering, route handlers, or server-only secrets, deploy it to Workers with the supported Next.js adapter and recheck the project there; this Pages configuration emits only static files.

References: [Cloudflare Pages: Deploy a static Next.js site](https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/), [Next.js static exports](https://nextjs.org/docs/app/guides/static-exports).

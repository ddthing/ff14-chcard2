# Git 배포의 직업 아이콘 누락 수정

2026-10-13 `https://ccard2.ffxiv.world/editor`에서 직업 문양이 글자로 표시된다는 사용자 제보를 확인했다. 실제 DOM은 `data-icon-source="fallback"`이었고, `/assets/ffxiv/jobs/xivapi/svg/red-mage.svg` 요청은 HTML 404 응답을 반환했다.

로컬에서는 Git에서 제외된 `.env.local`의 활성화 플래그를 사용했다. 환경 변수가 없는 배포 빌드는 Next.js에서 아이콘을 비활성화하고, 뒤따르는 패키징에서도 아이콘 파일을 제거하는 구조였다.

## 수정

`npm run build`와 `build:cloudflare`가 공유하는 `tools/build.mjs`에서 이 프로젝트의 검증된 로컬 XIVAPI 원본을 명시적으로 활성화한다. Next 컴파일과 정적 패키징에 동일한 환경 변수를 전달한다. 프로세스 환경의 명시적 `false`는 계속 우선하며, 직접 Next를 실행하는 경우의 기본 비활성화 동작도 유지한다. 컴파일에 실패하면 패키징을 실행하지 않고, 패키징 실패도 빌드 실패로 전달한다.

런타임 아이콘 원본·사용 승인 목록, 사진·카드 출력 경로, Square Enix 고지는 변경하지 않았다. 오래된 README의 빈 manifest 설명과 배포 출력 폴더 설명을 현재 구현에 맞췄다.

## 검증

- `.env.local`이 없는 별도 Git 소스 복사본에서 실제 프로덕션 빌드 성공 및 아이콘 파일 유지 확인.
- 같은 복사본에서 프로세스 플래그 `false`로 실제 빌드 성공 및 `dist/assets/ffxiv/jobs/xivapi` 제외 확인.
- 최종 빌드의 `out`·`dist`에서 manifest의 검증된 34개 SVG/PNG 원본 파일이 존재하고 SHA-256이 원본과 일치함을 확인했다. 33개 직업을 지원하고 마수조련사는 기존 대체 표시를 유지한다.
- 전체 테스트 317개 통과, 실패 0, 역사적 아카이브 29개 skip. 타입 검사·ESLint·프로덕션 빌드 통과.

배포 환경이 플래그를 명시적으로 `false`로 설정했다면 프로젝트 설정에서 값을 바꾸고 다시 빌드해야 한다. 이 기록의 검사 결과는 소스와 빌드 검증이며, 실제 사이트에서 아이콘 응답과 렌더링이 복구되었는지는 배포 완료 후 별도로 확인한다.

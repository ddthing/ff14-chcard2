# 이미지 내보내기 순차 검증

2026-10-11. 사용자의 “하나씩 검증 후 계속 진행”에 따라 디자인·모션 이후 이미지 출력부터 검사했다. 기준은 루트 `DESIGN.md`와 V3 QA 가이드다.

**현재 판정: 검증한 범위에서 통과.** 발견한 이름·구획선 충돌과 일본어 종족·부족 행 침범을 각각 수정·빌드·실물 재출력·독립 검토 후 닫았다. 최초 75건 이후 수정 재검수와 중간 실패 기록을 포함해 원본 Blob 122회, 일반 빌드 확인 2회를 기록했다. 파일 manifest 124행 중 2행은 초기 기준 파일과 중복 실행이다. 모든 가능한 문자열·플랫폼을 검사했다는 의미는 아니다.

## 실행 범위와 방법

- 별도 `http://127.0.0.1:4324`에서 실제 화면 조작으로 생성했다. 사용 중인 4322의 초안과 appearance는 변경하지 않았다.
- 기본 PNG 1×: 3마스터 × 5비율 × KO/EN/JA = 45개. 이름은 `긴 이름을 가진 에오르제아 모험가`, `Alexandria Winterbourne of Eorzea`, `エオルゼアを旅する長い名前の冒険者`다.
- ID 카드 EN: 5비율 × PNG/WebP × 2×/4× = 20개와 WebP 1× 5개.
- 시네마틱 KO와 에디토리얼 JA: 4:5 PNG/WebP 4× = 4개.
- 에디토리얼 JA 사진 조정: 위치 57% 14%, 확대 1.15의 PNG 1× 1개. 총 75회 생성이다. UI의 사진 설정을 원래 50% 8%, 확대 1로 복원했다.
- PNG와 WebP 각각 한 실제 브라우저 다운로드를 파일 헤더로 먼저 확인했다. 이후 다운로드 도구의 수분 지연 때문에, 같은 원본 Blob을 임시 loopback 서버에 보존했다. 75회를 OS 다운로드로 검증했다는 뜻은 아니다. 첫 PNG의 수집 파일과 실제 다운로드 파일 SHA-256은 일치한다. WebP의 결과 이미지와 실제 다운로드 파일 SHA-256도 일치한다.
- 임시 fetch/timing 코드는 검사 후 제거했다. 수집 서버도 종료했다. 수집 도구는 제품 경로에서 제거하고 `tmp/export-validation-2026-10-11/qa-export-capture.mjs`에 증거로 보관했다. 일반 빌드를 다시 생성했으며 소스·배포 JS에 검수 endpoint 문자열이 없다.

## 확인한 결과

75회 모두 생성 완료, 표시된 결과의 실제 bitmap 치수 일치, optical name 준비 완료, 원본 XIVAPI SVG 로드와 주요 필드 경계 포함을 확인했다. 주요 필드의 DOM 사각형끼리 540쌍을 비교했으며 에디토리얼 가로형 KO/JA의 이름·직업 wrapper가 조금 교차하는 두 사례가 나왔다. root가 원본을 전체 크기로 다시 확인한 뒤 독립 검토도 재확인했으며, 두 언어 모두 이름 마지막 줄을 정보표 구획선이 가로지르는 실제 결함이었다. 라이브 카드 폭 544px에서 JA 이름 wrapper는 구획선보다 7.953px 아래까지 내려왔다. 카드 바깥 포함 검사만으로는 잡히지 않는 결함이므로, 출력 완료 판정은 수정·재검수까지 보류했다. 초기 독립 검토의 “실제 글자와 구획선이 겹치지 않는다”는 판단은 철회했다.

| 비율 | 1× | 2× | 4× 요청의 실제 치수 |
| --- | --- | --- | --- |
| 1:1 | 1080×1080 | 2160×2160 | 4320×4320 |
| 4:5 | 1080×1350 | 2160×2700 | 4195×5243 |
| 3:4 | 1080×1440 | 2160×2880 | 4062×5416 |
| 9:16 | 1080×1920 | 2160×3840 | 3517×6252 |
| 16:9 | 1920×1080 | 3840×2160 | 6253×3517 |

1:1 이외의 4× 요청에는 22MP 제한이 적용된다. 화면이 실제 픽셀 크기와 제한 안내를 표시하고 파일명에 `capped`를 포함함을 확인했다. 출력 크기를 무조건 4배라고 표현하지 않는다.

일반 빌드에서도 JA 에디토리얼 WebP 1×가 1080×1350으로 완료됐다. 기록된 생성 시간은 739ms이고 console warning/error는 없었다. 이 수치는 한 실행 결과이며 전체 환경의 성능 보장은 아니다. 일반 빌드 실행은 수집 서버 없이 진행한 별도 76번째 확인이다.

## 검사와 증거

### 발견 결함의 순차 수정

1. 에디토리얼 16:9 이름과 구획선 충돌: `card-name-envelope.ts`의 해당 비율 측정 높이를 14→11.7cqi로 조정했다. 9%에서 35%까지의 실제 영역 14.625cqi 안에서 네 줄의 `.08em` 아래 여백과 세 `.25cqi` grid gap 및 약 1cqi 안전 간격을 확보한다. 이름 문자열과 CSS·렌더 경로·다른 비율·다른 마스터는 변경하지 않았다. focused regression은 네 줄의 실제 box overhead와 영문 짧은 이름의 기존 cap 유지를 확인한다.
   수정 후 에디토리얼 15개 기본 조합과 KO/JA 16:9 WebP 1×·PNG/WebP 4×의 6개를 재출력했다. JA 구획선 앞 간격은 1.054cqi, KO는 1.192cqi다. 1440/390/320px의 6개 실제 viewport에서도 간격이 유지된다. 원본 JA/KO 출력에서 마지막 줄과 구획선이 분리됨을 직접 확인했고, 독립 source/file 검토도 통과해 이 항목을 닫았다. 21개 파일의 형식·헤더·해시·상한은 모두 일치한다. KO/JA의 나머지 네 비율 출력은 수정 전과 byte-identical이며 EN의 실제 크기·위치도 유지됐다. `editorial-repair-runs.json`, `name-clearance-viewports.json`, `editorial-name-before.json`, `repair-qa-build.log`, `independent-name-repair-review.md`에 기록한다. 테스트 13개 통과, 기존 archive evidence 5개 skip이다.
2. 에디토리얼 JA 종족·부족 행: 4:5에서 race/clan이 각각 두 줄로 줄바꿈되며 다음 행 구획선을 침범한다. 1:1에서도 간격이 부족했고 3:4의 span은 행 경계보다 3.094px 아래까지 내려왔다. 3:4는 명백한 잉크·선 교차로 과장하지 않으며, 조각난 줄바꿈과 행 box 침범으로 구분했다. `ja-lineage-4x5-zoom.png`, `lineage-before.json`, `lineage-first-pass-runs.json`에 원본 증거를 보관했다.
   두 값이 모두 있는 JA 1:1/4:5/3:4 행만 1.5cqi와 nowrap을 적용했다. 1080px 원본에서 16.2px이며, 표 높이·다른 정보·다른 언어·9:16/16:9·원문·구분 기호는 유지한다. registry의 최장 표준 조합은 라라펠+사막 부족/평원 부족의 13글자 두 종류다. 최종 재출력 21건은 에디토리얼 15개 기본 조합, 두 최장 JA 조합의 4:5 WebP 4× 2건, 평원 부족의 3개 비율 PNG 1× 3건과 추가 사막 부족 4:5 PNG 1건이다. 모든 실제 정보 값의 세로 box가 자기 행 안에 들어갔다. `lineage-final-runs.json`은 최종 통과 21건이며, `lineage-repair-runs.json`은 수정 중 발견한 3:4 실패 1건을 포함한 중간 5건도 보존한다. sparse 행은 source/unit 검사로만 확인했으며 실물 출력으로 통과했다고 계산하지 않는다. focused localization/master 테스트 16개와 독립 source·21파일 검토를 통과해 이 항목을 닫았다. 근거는 `independent-lineage-repair-review.md`이며 수정된 세 언어 45개 연락판은 `contact-*-final-lineage.png`다.

## 범위의 한계

전체 270개 마스터·언어·비율·형식·배율의 직교 조합을 실행한 것은 아니다. 45개 기본 조합과 공통 출력 경로의 형식·배율·상한 대표 조합을 실행했다. 이번 정보표 데이터는 표준 종족·부족과 `Ember Bloom` 자유부대명이다. 허용 한도 48문자의 자유부대명 등 사용자 임의 긴 입력은 후속 입력 경계 검증 항목이며 이번 표준 조합 통과 범위에 포함하지 않는다. 브라우저 JPEG 스크린샷과 출력 PNG의 픽셀 차이는 캡처 압축·좌표 반올림이 섞이므로 동일성 판정에 사용하지 않았다. 실제 iOS/Safari·Android의 파일 저장, 인쇄/PDF, OS 동작 줄이기 실물은 이 기록의 통과 범위에 포함하지 않는다.

현재 checkout에 portable brain memory/protocol/CLI가 없어 해당 시스템에 기록했다고 주장하지 않는다. 이 문서와 실제 산출 파일이 검증 기록이다.

## 실제 브라우저에서 확인한 동작

- 로컬 정적 프로덕션 빌드에서 모바일 390×844, 데스크톱 1440×1080을 확인했다. 검수 전용 오리진을 사용해 기존 개발 서버의 초안과 분리했다.
- 홈의 실제 초안 재개, 스타일 선택의 쿼리 전달, 사진 시작, 사진·정보·디자인 탭, 모바일 직업 선택 시트를 확인했다.
- 이름 변경 → Undo → Redo → 새로고침 뒤 복원을 확인했다.
- 로컬 WebP 파일 업로드는 기존 초안 교체 확인을 표시한다. 수락 뒤 이름·캐릭터 정보를 유지하고 `계속해서 편집`에 포커스를 옮기는 것을 확인했다.
- 예시 카드 교체 취소 뒤 초안을 유지하는 것을 확인했다.
- 4× 요청 때 22MP 상한에 맞는 4195×5243 실제 치수를 보여주며, 처리 취소 뒤 편집 상태를 유지하고 다시 실행할 수 있음을 확인했다.
- 앱의 밝게/어둡게 전환 전후 카드 종이·잉크 CSS 값이 동일한 것을 확인했다.
- 완료 화면은 생성된 실제 Blob을 표시한다. 재렌더된 미리보기로 결과 파일을 대신하지 않는다.

## 실제 출력 검사에서 찾고 수정한 항목

1. 외부 SVG fragment 클립은 화면에서는 작동했으나 PNG에서 사진이 사각형으로 출력됐다. 원본 브러시 경로를 카드 내부 SVG defs에 포함하고, 각 인스턴스의 고유 ID를 사용한다. 내보내기 clone에서 `clip-path` 참조를 로컬 fragment로 유지하도록 수정해 실제 PNG에서 붓결을 재확인했다.
2. Editorial 9:16 예시에서 얼굴이 잘렸다. Coner 샘플의 해당 마스터·비율에만 초점 Y=20을 적용했다. 업로드 이미지나 기존 초안의 crop은 덮어쓰지 않는다. 새 캡처의 얼굴·눈이 보이는 것을 별도 검토로 확인했다.
3. 마스터와 공통 크레딧이 중복됐다. 공통 크레딧 한 개만 출력하며 새 135개 조합에서 중복 0을 확인했다.
4. Record 이름의 이전 세리프 스타일, 작게 표시되던 Editorial 직업 문양, 정보 라벨에 닿던 붓끝을 현재 Figma의 서체·문양 크기·인쇄 여백에 맞췄다.
5. 모바일 사진 업로드 영역을 56px 행으로 줄이고 조작 영역을 44px로 유지했다. 작은 직업 필터도 최소 너비 44px를 갖는다.
6. 크기 제한이 적용된 파일명은 `-capped`를 포함한다. 초기 다운로드·결과 문구·재다운로드가 동일한 이름 계산을 사용한다.

## 보존 및 검수 범위

- 안정적인 마스터 ID와 데이터 계약은 `2.6.4`, 새 시각 버전은 `3.0.0`이다. 저장 스키마를 변경하지 않았다.
- XIVAPI 원본 SVG/256px 이미지와 승인된 fallback만 사용한다. 직업 아이콘을 새로 마스킹하거나 그리지 않았다.
- 공식 에셋 플래그는 빌드 프로세스에 한해 활성화해 검수했다. 설정·환경 파일은 수정하지 않았다.
- PDF는 기존 브라우저 인쇄 경로를 유지한다. 이 검수에서 실제 인쇄 장치나 iOS/Android 네이티브 셸을 실행한 것은 아니다.
- Windows의 Chromium 기반 브라우저에서 확인한 결과다. Safari 및 실제 iOS/Android 장치 검수는 출시 전 QA 가이드의 별도 항목으로 남는다.
- 임시 `v3-design-proof` 제품 라우트는 제거했다. 재검수용 소스는 [renderer-fixture.tsx.txt](../../qa/v3-card-masters/renderer-fixture.tsx.txt)에 보관한다.

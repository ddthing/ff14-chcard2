# 네비게이션·모바일 작업 흐름 수정 및 엄격 검수

사용자 요청: 네비게이션과 UI/UX를 비판적으로 검수하고 우선순위대로 실제 수정. 기준일 2026-10-09.

## 우선 수정한 문제

1. **네비게이션의 의미와 일관성**: 홈·스타일·사진 선택·편집·출력 경로를 공통 모델로 연결했다. 데스크톱은 현재 페이지를 표시하며, 모바일은 ‘메뉴’ 버튼에서 경로와 언어·테마 설정을 제공한다. 브랜드는 홈 링크이고, 출력 화면의 ‘편집으로’는 실제 편집 경로로 돌아간다. 편집기의 주요 저장 행동과 문서명·저장 상태를 명확히 표시했다. 기존 헤더의 중복 CSS 규칙을 정리했다.
2. **모바일 폼 배경과 편집 문맥**: 이전 58dvh 패널 높이 제한과 V3 overflow 규칙의 충돌을 제거했다. 카드·작업 탭을 유지하면서 인스펙터 본문만 스크롤한다. 이름·자유부대·소개는 전체 폭, 짧은 필드는 나란히 배치하며 긴 선택 값은 줄바꿈한다. VisualViewport 변화에 맞춰 카드 크기와 입력 노출을 조절하는 경로를 추가했다.
3. **신규 카드 정보 정확성**: 새 업로드는 `profileOrigin: 'user'`인 빈 사용자 프로필로 시작한다. 모르는 레벨은 내부적으로 0을 사용하고 입력 및 카드에서는 표시하지 않는다. 예시 선택과 기존 초안의 사진 교체는 각각 기존 의미를 유지한다. 명시적 사용자 프로필에만 빈 fallback을 적용하며, 기존 버전·marker 없는 데이터의 정규화는 유지한다. 현재 스키마를 반복 migration으로 오인하던 canonical 검사도 보완했다.
4. **제작 시작 행동**: 홈의 주요 CTA를 소개 바로 아래로 옮겨 모바일 첫 화면에서 사용할 수 있게 했다.
5. **리팩토링과 작업 기록**: 변경되지 않은 입력·picker 하위 트리에 메모이제이션을 적용했다. 현재 폴더에 기존 Git 기록을 연결해 수동 복사 없이 변경을 추적한다. 로컬 배포 설정과 에셋 보관소는 Git에서 제외했다.

## 독립 검토에서 추가 수정한 사항

- 모바일 헤더는 두 줄 구성으로 실제 높이가 107px인데 기존 편집 화면은 56px로 계산해 문서가 51px 넘쳤다. 헤더와 편집·출력 화면이 같은 높이 토큰을 사용하도록 맞췄다. 데스크톱·태블릿 헤더는 56px이다.
- 현재 스키마의 빈 사용자 service 값을 migration으로 오인하던 fallback을 수정하고 `migrated:false` 테스트를 추가했다.
- 카드 렌더 경계에서 새로운 UI 전용 stage 높이 토큰을 초기화해 앱 테마·레이아웃 값의 유입을 차단했다.
- 정적 검수 서버가 Next static export의 RSC `.txt`를 잘못된 MIME으로 응답하던 것을 `text/plain`으로 수정했다. 빈 신규 카드가 전체 페이지 진입으로 열려도 정보 입력에서 시작하게 했다.

## 실제 검수 결과

- 최종 `npm test`: **소스 검사 238 통과, 0 실패**, 과거 렌더 아카이브 29개 그룹은 명시적인 skip 사유를 표시한다. 신규 생성·보존·복원·취소·레벨 생략·경로 모델 검사가 포함된다.
- `npm run test:archive`: 현재 로컬 아카이브를 포함해 **288 통과, 0 실패, 0 skip**. 아카이브를 요청했는데 필수 폴더가 없으면 오류로 종료한다. 이 검사는 과거 렌더 자료도 검사하며 이번 전체 출력 조합을 새로 만든 것은 아니다.
- 최종 린트와 프로덕션 빌드: 통과. 빌드의 TypeScript 검사 포함.
- 로컬 프로덕션 빌드: KO/EN/JA × 320/390/768/1440px × 5페이지 **60개 구성에서 가로 넘침 없음**.
- 390×844 모바일 정보 패널: 문서 높이 844px, 문서 스크롤 0. 자유부대 입력 중에도 카드가 y177–339에 남고, 입력이 y692–740, 인스펙터 하단이 y836으로 화면 안에 유지됨. 이전에는 패널이 490px에서 끝나고 카드가 y−500으로 사라졌음.
- 390×430 저높이 화면: 중복 캔버스 도구·패널 제목을 접는 compact 상태에서 인스펙터 본문 높이 168px, 이름 입력 y314–362, 문서 높이 430px로 확인. 실제 OS 키보드 대신 작은 가용 화면에 대한 검수다.
- 메뉴: 실제 현재 경로 표시, Escape 닫힘 및 메뉴 버튼 포커스 복구, 입력을 눌러 바깥 클릭 닫힘, 경로 이동 뒤 닫힘 확인.
- 모바일 메뉴에서 다크 테마 적용 후 본문이 해당 테마 배경으로 표시되고 문서 높이 844px 유지. 설정 내부 Escape 후 메뉴 버튼으로 포커스 복귀 확인.
- 신규 업로드: 별도 출처의 새 세션에서 실제 WebP 파일 선택. 예시 이름·직업·서버·자유부대·소개가 유입되지 않음. 정보 입력의 이름·레벨·자유부대가 빈 상태로 시작. 이름 입력, 레벨 93 입력 후 삭제, 새로고침에서 이름 보존·레벨 빈 값·카드 레벨 미표시 확인.
- 실제 PNG 1× 생성: 디코딩된 결과 이미지 **1080×1350**, 생성 완료 상태 확인. 앱 내부 준비·렌더 단일 관측 3285ms. 파일 저장 완료 자체나 전체 기기의 출력 속도를 보증하는 값은 아님.
- 출력의 ‘편집으로’ 이동 후 입력한 이름과 자유부대 보존 확인.

실제 iOS/Android 소프트 키보드를 이번 데스크톱 검수 환경에서 에뮬레이션하지는 않았다. VisualViewport 대응은 코드·정리 동작을 검토했고 실기기 키보드 검수는 남는다. 메모이제이션의 실제 FPS/INP 개선 수치는 이번에 측정하지 않았다.

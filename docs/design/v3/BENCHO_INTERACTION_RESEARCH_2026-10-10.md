# Bencho 인터랙션 연구와 적용 · 2026-10-10

사용자 요청: bencho.dev의 공개 자료를 전체적으로 살펴보고 프로젝트에 적극적으로 응용하되 불필요한 부분으로 범위를 넓히지 않는다.

## 확인 범위와 근거

- [Blocks](https://bencho.dev/): 실제 브라우저의 공개 목록은 48개다. 웹 텍스트 추출에서는 40개만 보여 브라우저에서 읽은 48개의 예제 링크를 기준으로 했다. 아래 표는 전체 목록을 작업 목적에 따라 분류한 것이다.
- [Sounds](https://bencho.dev/sounds): UI 음향 자료의 구성과 목록을 확인했다. 모든 음원을 청취하거나 도입하지 않았다.
- [Finds](https://bencho.dev/finds): 인터페이스 참고 사례 목록을 살펴보고 [시각적인 비율 선택](https://bencho.dev/finds/isaiah-aspect-picker)을 관련 참고로 골랐다. 외부 게시물 전체를 순회하지 않았다.
- [Bench](https://bencho.dev/bench): 예제를 배치하고 조정하는 캔버스라는 제품 설명을 확인했다. 회원 가입이나 개인 작업대 저장은 하지 않았다.
- [비율 예제](https://bencho.dev/blocks/aspect)는 실제로 세로 옵션을 선택해 미리보기와 선택 상태를 확인했다. 예제의 코드·이미지·음향을 복사하지 않았다.
- 현재 프로젝트의 V3 문서, 기존 [상호작용 계약](../interaction-system.md), 라이브 [Figma 디자인 패널 71:1239](https://www.figma.com/design/MqkXWfirWgjyyRbqGZjacF?node-id=71-1239)을 함께 대조했다.

공개 예제의 목록과 관련 조작을 연구했다는 의미다. 모든 예제의 내부 코드, 회원 기능, 접근성 준수나 동작 줄이기 지원을 검증했다는 뜻은 아니다. 아래 원칙은 관찰에서 도출한 프로젝트 적용 판단이다.

## 재사용할 원칙

1. 조작과 결과를 가깝게 둔다. 연속 조절은 바로 반영하고, 비율 같은 이산 선택은 전체 선택지를 읽을 수 있게 한다.
2. 현재 상태를 형태·텍스트·의미 속성으로 함께 드러낸다. 색과 애니메이션만으로 선택을 전달하지 않는다.
3. 피드백은 실제 작업 상태에서 나온다. 완료는 성공 이후에만, 오류에는 회복 경로를 제공한다.
4. 드래그에는 파일 버튼·키보드 같은 대안을 유지한다. 일반 변경에는 불필요한 확인 단계를 넣지 않는다.
5. 모션은 기존 120/180/220ms 토큰을 쓰고 변형·불투명도에 한정한다. 카드 비율·사진 조절 자체에 지연 애니메이션을 넣지 않는다.

## 이번 구현

- 디자인 인스펙터의 비율 선택을 다섯 개의 직접 선택 라디오로 제공한다. 각 옵션은 실제 종횡비 도형, 비율 숫자와 현지화된 용도를 표시한다. 메뉴를 열고 고르던 두 단계가 한 번의 선택으로 줄어든다.
- 작은 작업 도구에는 기존 compact 비율 메뉴를 유지한다. 두 표현은 같은 store와 지원 비율을 사용한다.
- 프로젝트 미리보기 버튼과 열린 영역을 연결하고 열림 상태를 노출한다. 보관함 트리거도 dialog의 열림 상태와 대상 ID를 제공한다.
- 원래 잘 갖추어진 업로드·팔레트·삭제 확인·저장·내보내기 상태는 기존 구현을 재사용한다.

카드 렌더러·사진 처리·출력·직업 자산·저장 스키마를 변경하는 작업이 아니다. 새 패키지나 외부 자산을 도입하지 않는다.

## 검증 기록

- `npm run typecheck`, `npm run lint` 통과.
- `npm test`: 248개 통과, 실패 0개, 아카이브 증거에 의존하는 기존 29개 skip. 이번 작은 표현·의미 속성 변경에 구현을 그대로 복제하는 테스트는 추가하지 않았다.
- 최종 `npm run build` 통과. 처음에는 Windows sandbox에서 경로 canonicalization 접근 오류가 발생했고 정상 로컬 권한으로 재실행했다.
- 실제 키보드: 1:1 라디오에서 ArrowRight로 4:5를 선택하고 실행 취소로 1:1 복원. 9:16 선택 후 새로고침에서도 캔버스 비율을 복원했다.
- KO/EN/JA × 320/390/1440px의 9개 화면 및 1024px KO 확인: 페이지 가로 넘침 없음. 새 선택지의 실제 최소 폭은 약 49.6px, 최소 높이는 72px였다. 일본어 설명은 필요하면 줄바꿈하여 잘리지 않는다.
- 프로젝트 모달: 트리거가 열릴 때 `aria-expanded=true`, `aria-controls`가 실제 dialog ID와 일치. 저장한 검수 카드의 미리보기도 확장 상태와 실제 이름 있는 region을 연결했다. Escape 후 트리거 포커스 복귀와 `aria-expanded=false` 확인.
- 다크 테마: 비율 선택 상태와 가로 넘침 없음 확인. 새 컨트롤의 reduced-motion 규칙은 CSS에서 확인했으며 OS 동작 줄이기를 직접 에뮬레이션하지 않았다.
- 브라우저 error 로그 0개. 독립 코드 검토에서 대상 변경의 P0/P1 지적 없음.

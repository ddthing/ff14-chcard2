## 단계 1 진행 기록

- 문제: inspector의 transform/overflow 안에 viewport 크기의 fixed popup이 놓여 모바일 목록이 잘렸다.
- 모바일에는 native `dialog.showModal()`을 사용해 top layer에서 렌더하고 데스크톱 inline combobox는 유지한다. 같은 DOM 조상에서 기존 editor 테마 토큰을 상속한다.
- visualViewport의 resize/scroll에 맞춰 선택창 경계를 갱신한다. 실제 OS 소프트 키보드 환경은 이번 도구에서 실행하지 못하며 해당 부분을 소스 검증으로 구분한다.
- 320px에서 선택 버튼 중앙과 absolute 지우기 버튼이 겹쳐 클릭이 값 삭제로 바뀌는 결함을 추가 발견했다. 지우기를 독립된 44px flex sibling으로 분리했다. QA 값은 undo로 복구했다.
- 첫 실물 검사에서 모달 이름이 외부의 inert label을 참조해 사라졌다. 모달 내부 header ID로 dialog/input/list의 접근성 이름을 연결하고 다시 빌드·AX에서 `직업`, `직업 옵션 검색`, `직업` 목록 이름을 확인했다.
- 320×844: 선택창 296×512px, y=166…678, 목록 높이 208.5px. 화면 안에 놓인다. 스크롤 후 마지막 바이퍼 행 y=621…673을 읽고 클릭 선택·닫기·trigger 복귀를 확인했다. 기존 적마도사 값으로 undo 복구했다.
- 정지한 pointer 아래로 목록이 스크롤될 때 `onMouseEnter`가 keyboard 활성 옵션을 덮어썼다. 실제 이동이 있는 pointer move에만 활성 상태를 변경하도록 수정했다. 마지막 바이퍼까지 ArrowDown 탐색이 유지되고 행 전체가 y=625…677로 모달 안에 보이는 것을 재검증했다.
- 다섯 picker × KO/EN/JA × light/dark × 320/390px = 60조건에서 모달/검색/목록 이름, viewport 경계, Escape 복귀가 통과했다. 추가로 320×480, 390×600, 900×844, 마지막 옵션 탐색을 확인했다. 901px에서는 기존 데스크톱 inline combobox 경로를 유지했다.
- 320px 선택 trigger 61×46px, clear 44×44px이며 영역이 겹치지 않는다. 관련 타입·lint·17개 focused test, 프로덕션 빌드와 독립 소스 검토를 통과했다. 범위 밖의 기존 release HTML whitespace는 수정하지 않았다.
- 포커스 단계의 데스크톱 pointer 확인에서 기존 desktop input과 clear 영역도 겹치는 것을 발견해 추가 수정했다. input/44px clear/비조작 arrow를 독립 grid 슬롯으로 배치했고 job/level만 desktop 3:1, level 최소 72px로 조정했다. 모바일의 같은 폭 두 열과 종족/부족 행은 유지한다.
- 데스크톱 1440px: input 130.5×44px, clear 44×44px의 끝/시작 x=1220.5로 겹침이 없다. 901/1440px 실제 input 클릭이 선택창을 열고 적마도사 값과 clear 버튼을 유지한다. 독립 source gate 및 재빌드 통과. 해당 증거는 `step1-desktop-followup/`에 분리했다.

- 원본 2px Stone ring을 보존하고 기존 foreground 역할의 1px keyline을 추가했다. globals·header·editor·ratio·create·templates·export의 실제 포커스 표면과 상위 specificity 예외를 처리했다.

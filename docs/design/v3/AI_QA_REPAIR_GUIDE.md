# AI 결과물 QA·수정 가이드

상태: V3 구현 검수 기준 · 2026-10-08

이 문서는 AI가 수정한 홈·편집기·카드 화면을 실제 Figma 제안과 제품 동작에 맞춰 검수합니다. “고급스럽다”라는 인상만으로 통과시키지 않고 시각 위계, 정보 정확성, 접근성, 업로드·저장·내보내기를 확인합니다. 디자인은 V3 마스터 스펙과 Figma가, 기능 여부와 데이터는 현재 코드가 근거입니다.

## 검사 전 기준

1. 같은 폴더의 MASTER_DESIGN_SPEC.md, DESIGN_TOKENS.md, SCREEN_AI_PROMPTS.md를 읽습니다.
2. [Figma V3 제품 화면](https://www.figma.com/design/MqkXWfirWgjyyRbqGZjacF?node-id=64-672)의 20개 프레임과 [V3 카드 보드](https://www.figma.com/design/MqkXWfirWgjyyRbqGZjacF?node-id=23-568)를 엽니다. 캡처 파일은 product-previews에 있습니다. 상태 파일과 캡처를 대조하며 Figma에 더 최근 사용자 수정이 있으면 최신 디자인을 따릅니다.
3. 변경 범위를 기록합니다. 사용자는 V3 UI 및 카드의 시각 재설계를 명시적으로 승인했습니다. 따라서 기존 V1 동결과 충돌하는 시각 가드는 승인 범위 내에서 업데이트할 수 있습니다. 카드 정보 구조, 로컬 저장, undo/redo, 접근성 의미, 마스터 ID, 단일 미리보기/내보내기 렌더러, 실제 export 계약과 XIVAPI 아이콘 출처는 보존합니다.
4. 모바일 390×844와 데스크톱 1440px에서 같은 데이터·사진·브라우저로 변경 전/후 캡처를 만듭니다. 카드 캡처는 마스터·비율·로케일·색 모드를 이름에 기록합니다.

## 카드 조합 매트릭스

모든 기본 조합을 최소 한 번 캡처합니다: 3 마스터 × 5 비율 × 3 로케일 = 45장.

| 축 | 필수 값 |
| --- | --- |
| 마스터 | Cinematic Gold / cinematic-master, Editorial Vermilion / editorial-master, Adventurer Record / identity-master |
| 비율 | 1:1, 4:5, 3:4, 9:16, 16:9. 4:5 화면을 늘려 다른 비율로 만들지 않음 |
| 로케일/이름 | ko/en/ja, 짧은 이름, 긴 한글 이름, 여러 단어의 라틴 이름, 중점·탁점 포함 일본어, 한자 이름 |
| 데이터 | 필수 정보만 채운 sparse와 가능한 값이 있는 full; 빈 필드는 출력하지 않음 |
| 사진 | 어두운 밤, 밝은 하늘, 얼굴이 왼쪽/오른쪽, 복잡한 배경, 원본 해상도가 낮은 장면 |
| 색상 | auto/job/custom; 셸 라이트/다크와 별도로 확인 |

전체 이름과 마스터별 primary 정보는 어떤 조합에서도 숨거나 잘리지 않아야 합니다. 이름을 자르는 대신 측정 기반 fit, 해당 비율의 타입 크기와 줄바꿈을 조정합니다.

## 행동 회귀 시나리오

| 흐름 | 확인 | 합격 기준 |
| --- | --- | --- |
| 시작 | 홈 → 템플릿 → 사진/샘플 → 편집 → 내보내기 | 경로와 선택 데이터가 이어지고 CTA가 실제 작업을 수행 |
| 업로드 | JPG/PNG/WebP 파일·드롭, HEIC 또는 손상 파일 | 지원 파일은 초안에 반영, 실패는 원인·지원 형식 안내, 기존 초안 보존 |
| 사진 | 위치·크기·밝기 변경, 초기화, 교체 | preview와 저장 값이 일치하고 드래그 history group을 한 번에 undo |
| 정보 | 이름·직업·레벨·월드/DC·종족/부족·FC·총사령부·언어·취향·소개·서비스 | label과 실제 필드가 정확히 연결되고 preview/export에 동일 값 |
| undo/redo | 사진·문자·마스터·비율 수정 후 되돌리기/다시 실행 | 최근 변경과 묶음 조정이 정확히 복원 |
| 저장 | 변경 후 새로고침/경로 재진입 | 이미지·crop·선택 카드·비율·필드 보존. 저장 전 상태를 완료로 표시하지 않음 |
| export | PNG/WebP, 1×/2×/4×, 5개 비율 | MIME·이름·헤더 치수·프리뷰 일치, 최대 22,000,000px 및 8192px edge 준수 |
| PDF 인쇄 | /export에서 PDF 인쇄 선택 | 기존 window.print()와 print stylesheet를 유지하고 현재 카드/비율을 브라우저 인쇄 대화상자에 전달. 별도 앱 PDF 파일 생성으로 설명하지 않음 |
| 실패 | 폰트/이미지 로딩 또는 renderer 실패 | 성공으로 가장하지 않고 적절한 오류·재시도·편집 복귀 제공, 초안 보존 |

1080×1350의 4:5 카드에서 요청 4×는 23,328,000px로 22MP 상한을 초과합니다. 실제 export 크기 계산 결과를 표시합니다. 버튼 이름만 보고 출력이 4×라고 단정하지 말고 다운로드된 이미지 헤더 치수를 검사합니다.

## 접근성·자산·렌더러

- 모바일 터치 목표는 44×44 CSS px 이상을 기본으로 합니다. V1에서 측정한 24px은 과거 최소 기준의 증거이지 V3 기준 충족 증거가 아닙니다.
- 마우스 없이 탭·검색·파일 선택·슬라이더·모달을 사용합니다. hover 전용 동작이 없어야 하고 키보드 포커스가 보여야 합니다.
- 입력은 label과 연결합니다. 오류는 관련 입력에 연결하고 alert/live region으로 알립니다. 선택·상태를 색만으로 표시하지 않습니다.
- 패널/대화상자는 열릴 때 제목과 포커스를 전달하고, 닫기/Escape 뒤에는 원래 트리거로 돌아옵니다. OS 키보드와 안전 영역이 조작부를 가리지 않아야 합니다.
- 긴 이름·고대비·200% 확대·prefers-reduced-motion을 포함합니다. 애니메이션 없이도 필수 상태와 정보가 전달되어야 합니다.
- 홈, 갤러리, 편집기와 export는 같은 카드 마스터 렌더러와 같은 카드 데이터·이미지·폰트를 사용합니다. 화면별로 카드 마크업을 복제하지 않습니다.
- 직업 마크는 기존 resolver가 현재 크기와 용도에 승인한 로컬 XIVAPI 원본만 씁니다. 수제 마스크, derived mask/SDF, 재생성 SVG, 외부 원격 아이콘은 P0입니다. 원본이 없거나 큰 사용에 승인되지 않은 경우 텍스트/역할 폴백을 씁니다.
- Editorial은 실제 사용자가 올린 원본 사진과 조정값을 불규칙한 붓 알파 윤곽으로 자릅니다. 사진 자체를 생성·재칠하지 않습니다. 등록된 폰트 경로를 사용합니다.

## 오류별 좁은 수정

### Editorial 경계가 물결처럼 보임

**원인/수정:** 파도형 CSS/벡터를 Figma V3의 단일 붓 윤곽 알파로 교체합니다. 같은 이미지 crop을 마스크 안에 유지합니다. 사진 전체를 AI 재생성하거나 시안 캡처를 배경 이미지로 쓰지 않습니다.  
**재검사:** 얼굴·사진 내부에 투명 구멍이 없고 외곽에 흰 halo, 반복 곡선, 잘린 붓끝이 없는지 1×/2×/4×와 preview/export에서 확인합니다.

### 미리보기가 마스터보다 어둡거나 export와 다름

**원인/수정:** 같은 master ID, data, palette, crop, color mode를 프리뷰와 숨겨진 export surface에 전달하는지 추적합니다. 앱 셸 테마가 카드 CSS 변수를 덮는지 확인하고 화면 전용 오버레이를 제거합니다. 같은 렌더러의 계산 입력을 고칩니다.  
**재검사:** Light/Dark 셸만 바꿔도 카드색은 고정이고 사진·타입·재료·필드가 프리뷰와 산출물에 일치합니다.

### PNG가 22MP를 넘거나 4×라고 오인됨

**원인/수정:** 기존 22,000,000px 및 8192px 제한과 실제 사이즈 계산을 보존합니다. effective dimensions를 UI에 표시합니다. 고정 4× 이름/설명으로 실제 배율을 과장하지 않습니다. 상한을 올리거나 파일 헤더 검사를 빼지 않습니다.  
**재검사:** 5개 비율에서 PNG/WebP 헤더와 MIME·파일명·성공/오류 안내가 실제 결과와 일치합니다.

### 필드 레이블·역할·값 불일치

**원인/수정:** 화면 label → 카드 데이터 필드 → 마스터의 출력 필드를 추적합니다. World/DC, Race/Clan, jobId와 직업 표시명, service/region을 서로 바꾸지 않습니다. Figma 표현이 현재 데이터에 없으면 실제 지원 필드로 문구를 맞추거나 요구 간극을 기록합니다.  
**재검사:** KO/EN/JA, 저장/reload, undo/redo, preview/export에서 동일한 속성이 유지됩니다.

### 미지원 계정·클라우드·PDF 파일 생성 약속

**원인/수정:** 아직 구현되지 않은 계정·동기화·서버 전송·별도 PDF 파일 생성 버튼이나 약속을 제거합니다. 기존 PDF 인쇄 동작은 삭제하지 않고 현재 카드와 비율을 사용하는 window.print() 및 print stylesheet에 연결합니다. 새 서버 전송이나 개인정보 흐름을 시각 작업에 섞지 않습니다.  
**재검사:** PDF 인쇄가 브라우저 인쇄 대화상자를 열고 인쇄 레이아웃에는 카드만 포함됩니다. 화면 문구·접근성 label이 미지원 클라우드 또는 별도 PDF 생성이 이미 구현된 것처럼 말하지 않습니다.

### hover-only 또는 작은 클릭/탭 영역

**원인/수정:** 버튼·링크 같은 실제 의미 요소에 동작을 연결하고, hover는 시각 피드백에만 씁니다. 포커스 상태와 44×44 CSS px 타깃을 토큰에 반영합니다.  
**재검사:** 터치·키보드·마우스가 같은 동작을 수행하고 label, focus, 선택 상태가 보이며 확대해도 겹치지 않습니다.

## 테스트 명령과 오래된 V1 가드

코드 변경 후 실행할 기본 검사:

- npm run typecheck — TypeScript 및 데이터 계약
- npm run lint — 코드 품질 및 지원되는 접근성 진단
- npm test — tools/run-tests.mjs가 tests/*.test.mjs 전체 실행
- npm run build — 프로덕션 Next.js 빌드

V3는 사용자가 승인한 시각 재설계이므로 과거 버전·픽셀·잠금 규칙 중 실제로 대체된 기대값만 새 계약에 맞춰 갱신합니다. 예를 들어 tests/master-freeze.test.mjs가 구버전 시각 잠금을 강제하면 버전과 시각 기대만 검토합니다. primary 정보, 마스터 ID와 순서, 비율, 저장·undo/redo, 아이콘 출처, export 상한, 키보드 동작 테스트를 삭제하거나 느슨하게 바꾸지 않습니다.

tools/verify-phase2171-freeze.mjs의 이전 소스 해시 검사는 V1 소스 묶음에 대한 이력입니다. V3 승인 범위의 파일이 옛 보호 목록과 겹치면 그 해시 불일치를 재설계 실패라고 부르지 않습니다. 새 보호 범위와 변경 허용 범위를 명시하고 보존해야 할 실제 행동을 테스트합니다. 가드 자체를 삭제하거나 모든 변경을 허용하도록 약화하지 않습니다. CSS 문자열 검사에만 머물지 말고 실제 입력, UI 상태 전이, 저장, 파일 헤더, 오류 복구, 키보드 동작을 확인합니다. 실행하지 않은 명령은 통과했다고 기록하지 않습니다.

## 종료 기준

- P0/P1이 0건이며 P2의 수정 또는 문서화 근거가 있습니다.
- 20개 화면의 Figma ID·경로·실제 상태를 확인했습니다.
- 3×5×3 기본 카드 매트릭스와 긴 이름, sparse/full 데이터가 검수됐습니다.
- 업로드·조정·undo/redo·저장/reload·PNG/WebP 성공과 실패를 확인했습니다.

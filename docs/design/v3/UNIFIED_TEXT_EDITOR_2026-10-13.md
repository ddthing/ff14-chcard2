# 카드에서 선택하는 공통 내용·서체 편집기

2026-10-13 사용자가 승인한 카드 직접 선택, 내용과 서체의 공동 편집, 폰트 등록 구조 정리와 모바일 헤더 축소를 구현했다.

## 구조

- 작업 탭은 사진·내용·디자인으로 구분한다. 내용에는 이름·소개, 캐릭터 정보, 카드 문구를 묶는다.
- 실제 카드의 텍스트를 고정된 항목 ID로 연결한다. 번호는 위치 안내만 담당하며 저장 키가 아니다. 카드 선택과 항목 목록 선택은 같은 편집 대상을 가리킨다.
- 공통 편집기에 내용과 글꼴·크기를 함께 두고 굵기·자간은 추가 조절로 제공한다. 전체 카드의 서체 기본값과 개별 항목 설정을 구분한다.
- 편집 번호는 카드 렌더러 밖에서 표시하며 저장 이미지에 포함하지 않는다. 카드 렌더러와 내보내기는 같은 문구·서체 데이터를 사용한다.
- `textOverrides`와 `textTypography`는 기존 디자인 데이터에 선택적으로 추가한다. 예전 문구 묶음·서체 그룹 설정은 기존 카드의 기본값으로 계속 읽는다.
- 폰트 등록 목록에서 CSS와 package 로딩 모듈을 생성한다. `npm run fonts:generate`와 `fonts:check`를 제공하며 배포 빌드에는 생성 파일·자산 검사를 포함한다. 폰트 추가 절차는 [폰트 등록 가이드](../../fonts/ONBOARDING.md)를 따른다.
- 모바일 헤더는 한 줄 56px이며 메뉴·홈·주 행동의 조작 영역은 44px 이상이다. 저장 상태와 오류 안내, 언어·테마·메뉴 동작은 유지한다.

## 검증

- 타입 검사·ESLint·폰트 생성 파일 검사·프로덕션 빌드·`git diff --check` 통과. 전체 테스트 결과는 `tmp/unified-text-final-tests.txt`에 보관한다.
- 1440px에서 세 마스터 × 다섯 비율의 15조건을 실제 렌더링했다. 사용자 문구·개별 글꼴·125% 크기가 적용되고, 텍스트 범위와 페이지가 카드/뷰포트 밖으로 넘치지 않았다. 에디토리얼은 96자 일본어 문구와 Noto Sans JP, 나머지는 한글 문구와 Gmarket Sans를 사용했다. 결과는 `tmp/unified-text-final-matrix.json`에 보관한다.
- 모바일 390px에서 카드 번호 선택, 카테고리 선택, 내용 입력과 서체 조절의 공통 시트를 확인했다. 조밀한 정보 항목은 선택 목록으로 접근하고, 선택된 항목의 번호는 카드에 유지한다.
- 헤더는 320·390·640·641·900·901·960·961·1440px에서 56px였다. 보이는 헤더 행동은 44px 이상의 조작 영역이며 가로 넘침이 없었다.
- 시네마틱 인용문 수정 → Gmarket Sans 선택 → 서체/문구 순서로 Undo → 두 번 Redo → 새로고침에서 문구와 글꼴 복원을 확인했다. 보관함 저장·다시 열기·복제의 두 편집 맵 보존과 저장 후 원본 객체 변경의 격리도 테스트했다.
- 부족·데이터 센터·서비스/지역의 카드 선택이 해당 복합 선택기의 정확한 조작부로 이동함을 확인하고, 늦게 열리는 설정 영역의 포커스 재조회 횟수를 제한했다.
- 실제 PNG 4:5는 2,160×2,700, WebP 16:9는 3,840×2,160으로 생성·디코딩됐다. PNG의 한글 사용자 문구/Gmarket Sans 및 WebP의 긴 일본어 문구/Noto Sans JP가 실제 출력된다. 카드 안에 편집용 번호가 없음을 DOM 경계와 출력 미리보기에서 확인했다.
- 긴 문구의 가로 넘침과 줄바꿈이 많은 경우의 반복 맞춤 계산을 수정했다. 항목별 문자·줄바꿈 한도를 입력기와 저장 정규화가 공유하며 IME 조합 중에는 값을 자르지 않는다. 출력은 사용자 문구의 맞춤 완료도 기다린다.
- 예전 역할 서체는 상속하고 추가 조절에서 그룹 초기화가 가능하다. B/C 실험형은 기존 캐릭터 입력과 카드 전체 서체를 유지하고, 적용되지 않는 개별 항목 편집을 노출하지 않는다. A로 돌아오면 개별 편집 맵이 보존된다.
- 폰트 생성기의 22개 로컬 face 선언·파일 순서·문자 범위는 기존과 동일하다. 선택 목록과 ID 조회는 등록 정보에서 생성·캐시하며 숨긴 등록 폰트의 기존 저장 ID도 읽는다.

브라우저 검수는 격리된 저장소와 개발 서버에서 진행했다. 전체 언어·폰트·입력 길이의 모든 교차 조합이나 브라우저 FPS를 측정했다고 주장하지 않는다. Node 24.13.1을 검증·배포 런타임으로 고정했다. Cloudflare의 버전 파일 지원은 [공식 빌드 환경 문서](https://developers.cloudflare.com/pages/configuration/build-image/)를 확인했다.

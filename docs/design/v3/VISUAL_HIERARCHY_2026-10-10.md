# 홈 시각적 위계 리팩토링 · 2026-10-10

사용자 요청: 현재 화면의 시각적 위계를 엄격하게 확인하고 리팩토링.

Dense Home의 배치·밀도와 Clean Studio의 짧은 문구를 유지하면서 홈과 compact 프로젝트 목록의 우선순위를 정리했다. Stone 테마, 카드 마스터, 서체 및 기존 기능 경계를 따른다.

## 확인한 문제와 수정

| 문제 | 수정 |
| --- | --- |
| 만들기·저장·각 프로젝트 열기가 모두 채워진 버튼으로 경쟁 | 기본 홈에서는 카드 만들기만 전역 주 행동으로 채운다. 편집 계속하기·열기·저장은 테두리 보조 행동, 비교·목록 유틸리티는 텍스트 행동으로 둔다. 저장 폼에 포커스가 있을 때만 저장 버튼을 채워 해당 작업을 강조한다. |
| 초안 이름과 직업·서버가 서로 먼 열에 배치 | 이름과 메타데이터를 `draftIdentity` 안에서 묶고, 초안 레이블·저장 상태와 함께 일관된 그룹으로 구성한다. |
| 모바일 보조 레이블이 12px 미만 | 홈의 레이블·메타데이터·카드 캡션·푸터를 최소 12px로 조정한다. 카드 작품 내부 타이포그래피는 별도 계약을 유지한다. |
| 보관함 h2 다음 프로젝트 제목 h4 | 프로젝트 제목을 h3로 수정해 UI 제목이 h1→h2→h3로 이어지게 한다. |

홈 섹션 제목은 18px semibold, compact 프로젝트 이름은 14px semibold, 메타데이터는 12px muted로 구분한다. 스타일의 선택 상태는 배경·2px 하단선·체크로 유지하고 키보드 포커스는 별도 외곽선으로 표시한다. 모바일의 편집 계속하기도 테두리를 유지한다. 푸터의 중첩 opacity를 제거했다.

보관함 compact 규칙은 `data-compact` 안에 한정했다. 편집기 기본 보관함은 기존 제목 크기와 버튼 표시를 유지한다. 열기의 보이는 문구는 KO/EN/JA에서 짧은 동사로 정리하고, 접근성 이름에는 프로젝트 이름을 계속 포함한다. 확인·취소·저장 오류·live region을 유지한다.

## 실제 비교

별도 검수 origin `127.0.0.1:4324`에서 같은 초안과 저장 프로젝트 두 개를 사용했다. 사용 중인 `4322`의 저장 데이터를 변경하지 않았다.

- 저장 이름을 입력하고 폼에서 포커스를 뺀 기본 화면: 채워진 주요 행동이 기존 4개에서 카드 만들기 1개로 줄었다.
- 저장 폼에 포커스가 있는 화면: 카드 만들기와 현재 카드 저장 2개가 채워진다. 전역 시작 행동과 현재 입력 작업을 구분한 의도된 상태다.
- 데스크톱 초안 그룹: 이름의 X가 약 525px에서 131px로 이동하고 직업·서버가 바로 옆 약 230px에 이어진다.
- UI 제목: h1 43.2px → 섹션 h2 18px → 프로젝트 h3 14px. 공통 카드 렌더 범위 내부 제목은 이 UI 검사에서 제외했다.

## 검증

- 전체 테스트 248개 통과, 실패 0개, 기존 아카이브 검사 29개 skip. TypeScript·ESLint·프로덕션 빌드 통과.
- KO/EN/JA × 1440/1024/768/390/320px의 15개 홈 검사: 가로 넘침, 접근성 참조 ID 누락, 보이는 비카드 UI의 12px 미만 레이블 없음. 스타일 조작 영역 44px 이상.
- 스타일 선택값이 만들기 링크에 전달됨을 확인했다.
- 프로젝트 열기 확인창에서 Escape 후 해당 프로젝트 열기 버튼으로 포커스 복귀를 확인했다.
- 다크 1440px 홈은 가로 넘침 없이 같은 행동·제목 위계를 유지한다.
- 편집기 보관함에는 compact 규칙이 없고, 제목 40px·프로젝트 제목 20px의 기본 표시를 유지한다. Escape 후 내 프로젝트 트리거로 포커스 복귀를 확인했다.
- 독립 소스 검토에서 행동 경쟁·작은 레이블·초안 그룹·제목 단계의 네 지적이 해결되었음을 확인했다.

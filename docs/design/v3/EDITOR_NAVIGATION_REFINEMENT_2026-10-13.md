# 접기 위치·번호 목록·모바일 작업 바 적용

이전 구현 기록. 현재 접기·더보기·선택 규칙은 [위계·선택·수치 조절 정리](./EDITOR_HIERARCHY_DENSITY_2026-10-13.md)와 루트 DESIGN.md를 따른다.

2026-10-13 사용자가 [수정안](./proposals/EDITOR_NAVIGATION_PROPOSAL_2026-10-13.md)을 승인한 후 반영했다. 이 기록과 함께 루트 DESIGN.md §5.1을 갱신했다.

- 헤더에서 항목 접기를 제거하고 데스크톱 `편집 항목` 제목 오른쪽에 배치했다. 접으면 레일과 목록이 함께 사라지며 캔버스가 왼쪽부터 공간을 사용한다. 다시 열기는 캔버스 왼쪽 위에서 제공한다. 태블릿은 같은 위치에서 항목 서랍을 연다.
- 실제 편집 가능한 문구를 `1. 이름`처럼 번호부터 표시하고 현재 문장을 아래에 배치했다. 문구 행의 장식 아이콘과 오른쪽 번호를 제거했다. 오른쪽 항목 선택도 번호와 제목을 가까이 두었다. 작은 정보의 서체는 하나의 정보 세트로 유지한다.
- 사진의 레이블과 숫자를 같은 행, 슬라이더를 바로 아래에 둔다. 확대는 백분율로 입력하고, 작성 중인 첫 숫자가 범위 교정으로 바뀌지 않도록 초안 값을 유지한다. 완료 시 75–250% 범위를 적용한다. 숫자 입력 폭도 세 자리 값과 소수점이 잘리지 않도록 확보했다.
- 모바일 헤더 아래 작업 줄을 제거하고 하단에 사진·문구·디자인·더보기의 단일 작업 바를 배치했다. 별도 카드 위 더보기와 비율 칩을 제거했다. 메뉴의 실제 조작부는 같은 컴포넌트를 하단으로 연결해 동작 중복을 피한다.
- 속성 시트는 작업 바 위에서 열리고, 짧은 화면 또는 키보드 입력 시 작업 바를 숨겨 입력 공간을 확보한다. `카드 보기`로 돌아갈 수 있다. 글꼴 선택기 포털 입력도 같은 입력 모드에 포함한다. 모바일 미리보기의 도구는 존재하지 않는 속성 패널을 참조하지 않는다.
- 390px에서는 문서 이름을 유지하고 370px 이하에서 생략한다. 언어 선택과 이미지 저장은 유지한다. 선택·포커스·시트 전환은 기존 토큰과 reduced-motion 규칙을 사용한다.

## 검증

- 전체 테스트: 402개 중 373개 통과, 기존 이력 검증 29개 보류, 실패 0개.
- ESLint, TypeScript, 글꼴 생성 파일 동기화, 프로덕션 빌드 통과.
- 390×844 카드 보기·문구 시트와 1440×900 펼침·접힘 화면을 실제 브라우저에서 확인했다. 데스크톱 접힘 상태에서 캔버스 x=0, 재열기 버튼 포커스 복귀를 확인했다.
- 1024px 항목 서랍의 Tab 이동과 Escape·제목 닫기·배경 클릭의 포커스 복귀, 320/390/480px와 900/901px·1180/1181px 경계 및 가로 화면을 확인했다. 독립 최종 검수에서 접기 이름·44px 조작 영역, 사진 조절 정렬과 `9` 초안 → `90%` 입력이 통과했다. [최종 검수 데이터](../../../tmp/navigation-refinement-browser/evidence/final-verification.json). 문구 목록을 실제로 펼친 후 `1. 이름` 선택과 `character.name` 입력의 연결도 확인했다. [문구 선택 데이터](../../../tmp/navigation-refinement-browser/evidence/root-text-row-check.json).
- 모바일 미리보기에서 패널 참조·열림 표시를 제거하고 문구 도구를 누르면 편집기로 복귀하는 것을 확인했다. 텍스트 입력에서 visualViewport 높이 400px, 글꼴 포털 검색에서 360px을 모의했을 때 작업 바가 숨겨지고 입력칸이 보였으며, 844px 복원 후 작업 바가 다시 표시됐다. 이는 브라우저 모의 검증이며 실제 기기의 소프트 키보드 테스트로 표현하지 않는다. [추가 검증 데이터](../../../tmp/navigation-refinement-browser/evidence/root-extra-checks.json).
